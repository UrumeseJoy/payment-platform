# EC2 deployment

This is a single-EC2, Docker Compose deployment for demonstration and learning. It runs the
Spring Boot API, Postgres, Redis, Kafka, and Nginx together. It is not a production topology.

## Prerequisites

- Amazon Linux 2023 EC2 instance (recommended: `t3.medium`, 30 GiB storage).
- Inbound security-group rules: SSH (22) from your IP and HTTP (80) from your IP initially.
- Do not expose Postgres (5432), Redis (6379), Kafka (9092), or the application port (8080).
- Docker Engine and Docker Compose plugin installed on the instance.

## First deployment

On your Mac, push the repository to GitHub. On the EC2 instance:

```bash
git clone https://github.com/UrumeseJoy/payment-platform.git
cd payment-platform
cp .env.example .env.production
chmod 600 .env.production
```

Edit `.env.production` and replace `POSTGRES_PASSWORD` with a value generated by:

```bash
openssl rand -base64 32
```

Validate and start the stack:

```bash
docker compose --env-file .env.production config -q
docker compose --env-file .env.production up -d --build
docker compose ps
docker compose logs -f app
```

## Verify

From your laptop:

```bash
curl -i -X POST http://YOUR_EC2_PUBLIC_IP/payments \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-payment-001' \
  -d '{"merchantId":"demo-merchant","amount":100.00,"currency":"USD"}'
```

The immediate response should be `201 Created` and `CREATED`; authorization/capture continue
asynchronously through Kafka. The current API has no `GET /payments/{id}` endpoint. To inspect
state on EC2:

```bash
docker compose --env-file .env.production exec postgres psql -U payment_app -d payment_platform \
  -c 'SELECT id, status, amount, created_at FROM payments;'
```

## Updating

```bash
cd ~/payment-platform
git pull --ff-only
docker compose --env-file .env.production up -d --build
docker compose logs -f app
```

## Scope and security

- The API has no authentication or TLS yet. Keep HTTP restricted to your IP for this demo.
- Add a domain, HTTPS, and API-key authentication before broad public access.
- `.env.production` is intentionally ignored and must never be committed.
- `docker compose down -v` permanently deletes the Postgres/Kafka data volumes; do not use it
  unless you explicitly intend to reset all local deployment data.
